# Alignment with omnipackage-rs

Oleg's own tool `omnipackage` (`~/projects/omnipackage/omnipackage-rs`, docs in `~/projects/omnipackage/omnipackage-docs`) builds RPM/DEB/pacman packages inside per-distro containers and publishes signed repos to Cloudflare R2. packman-nova should live next to it: same R2 bucket, same GitHub Actions shape, same conventions. This doc records what to copy and where omnipackage does not fit.

## Conventions to reuse
- **Container runtime:** plain rootless `podman run --rm` (autodetect podman, then docker, override with `OMNIPACKAGE_CONTAINER_RUNTIME`). `host` mode for CI jobs that already run inside the distro image (no nested containers). packman-nova's builder adds `--privileged` because obs-build chroots; keep it optional so `host` mode works in a GitHub `container:` job.
- **Config style:** one `config.yml`, YAML anchors (`common: &common`, `<<: *common`), `${ENV_VAR}` expansion before parse, `.env` via dotenvy with process env winning, `secrets:` map redacted from logs. Version extractors: `file` regex, `shell`, `constant`.
- **Logging/CLI:** `HH:MM:SS [I] msg`, `$ cmd` echo, `--fail-fast` vs aggregate errors, timing lines, clap with flattened arg groups. `anyhow` everywhere, builder-style `Command`.
- **R2:** bucket `repositories`, public URL `https://repositories.omnipackage.org`, `endpoint: ${CLOUDFLARE_R2_ENDPOINT}`, `region: auto`, `force_path_style: true`, checksum `WhenRequired`, adaptive retries. Layout `<path_in_bucket>/<distro_id>/{*.rpm, repodata/, <slug>.repo}` plus `install.{html,json,sh}` and `badge.svg` at the prefix root. Optional Cloudflare cache purge by prefix. `.env` keys: `CLOUDFLARE_R2_ENDPOINT`, `CLOUDFLARE_R2_ACCESS_KEY_ID`, `CLOUDFLARE_R2_SECRET_ACCESS_KEY`, `CLOUDFLARE_ZONE_ID`, `CLOUDFLARE_API_TOKEN`, `GPG_PRIVATE_KEY_BASE64`.
- **Signing:** RSA 4096 key, no passphrase, stored as one-line base64 of the ASCII armor; every gpg call in a temp `GNUPGHOME`; `rpm --addsign`, `createrepo_c`, detached `repomd.xml.asc`, public key as `repodata/repomd.xml.key`; generated `.repo` file with `gpgcheck=1`.
- **GitHub Actions:** reusable workflow with `list-distros` JSON feeding a matrix, `fail-fast: false`, `concurrency: group: <repo>-<distro>` without cancel (repodata is not safe for concurrent writers), whole `.env` in one secret (`OMNIPACKAGE_DOTENV`), x86_64 on `ubuntu-24.04`, aarch64 on `ubuntu-24.04-arm`, weekly `prime` job that bakes build deps into a GHCR image cache, CLI installed via `uses: omnipackage/omnipackage-rs@stable`.

## Where omnipackage does not fit packman-nova (as of 0.1.20)
1. **Raw spec + prjconf:** omnipackage always renders the spec through Liquid, tars the whole source dir as `Source0`, runs `rpmbuild -bb` with no `--define`, and has no notion of OBS project config (`Macros:`, `Prefer:`, `Substitute:`, `Release:`). packman-nova needs Factory specs untouched, multiple sources/patches, and the macro set from `docs/04`. obs-build inside the container does all of this; see `tools/build-in-container.sh`.
2. **BuildRequires resolution:** omnipackage installs a hand-written `build_dependencies` list. Factory specs carry 30-100 BuildRequires that change over time; they must be resolved from the spec (obs-build does it).
3. **Own repo as build input:** tier N+1 needs tier N rpms; omnipackage's setup order (install deps, then `before_build_script`) cannot add our repo before dependency installation. obs-build's `--rpms` / `--repo` covers it.
4. **Repository model:** one package per `<path>/<distro>` dir, full re-sync that deletes anything not in the local dir, `retain_packages` by count. packman-nova is one repo with ~45 source packages updated independently; needs incremental add/replace and per-package retention. No arch in the path, no `src/` repo, flat dir.
5. **Distro list is compiled in** (`distros.yml`); a custom builder image cannot be selected from config.

## Proposed split
- Build: obs-build in `packman-nova-builder` image (`container/`), driven by a small CLI or scripts in this repo. Later, if worthwhile, add a "raw spec / obs-build" backend to omnipackage-rs itself.
- Publish: either (a) extend omnipackage with a multi-package incremental RPM repo mode and reuse its R2/GPG/locking code, or (b) copy `publish/s3`, `publish/locking.rs`, `publish/cloudflare.rs`, `gpg.rs` into a Rust CLI here. (a) benefits omnipackage users too; decide after milestone 2.
- Publish path proposal: `repositories/packman-nova/tumbleweed/{x86_64,aarch64,noarch,src}/` with one `repodata/` at `tumbleweed/` (single repo, `baseurl=.../tumbleweed`), or per-arch repos if omnipackage's per-distro-dir model is kept.
